# 两卡逐请求缓存诊断

这是分别重跑的带埋点 KV 和 KV+Progress，对照与正式性能组分开；两条闭环回放的请求到达时间和缓存状态会变化，不能把差异直接归因于 Progress。

128 个请求完整匹配。KV 的请求级新算 input token 合计 **3,796,544**，KV+Progress 为 **3,736,320**（-1.59%）；两个合计均与各自 worker 的计数器一致。
逐请求看，新算 token 增加 **19** 个请求、减少 **29** 个、相同 **80** 个；增加的请求合计多算 **482,912** token，减少的请求合计少算 **543,136** token。
对两台同构 worker 做一次全局编号对齐后，有 **54** 个请求的处理 worker 不同；其中 **11** 个同时出现缓存命中 token 减少，合计少命中 **248,416** token。这只是相关关系，缓存内容和到达顺序也可能不同。
Progress 组实际选中的节点，在 **6** 次请求中具有高于候选最小值的预估新增 token，差值合计 **276,928** token；成本同时包含负载和在途 prefill，不能据此判定选路错误。

## 成本公式的具体取舍

在 **7** 次同状态影子最低分变化中，有 **4** 次实际选中节点的预估新增计算量高于另一候选；这 4 次的预估差值合计 170,368 token。这是候选节点上的 Router 估计差值，不能当作另一节点已实际执行的计算量。
例如一个 49,664-token 请求，在 Progress 开启时选择了节点 A：预估新算 49,664、在途剩余 1,920、在途请求 7，分数 412,672；节点 B 预估新算 640、在途剩余 46,784、在途请求 8，分数 426,816。分数更低的 A 被选中，虽然其预估新增计算量高 49,024 token。
在同一实际状态下保留初始账本时，B 的剩余预估为 2,496、影子分数为 28,224，于是影子计算选 B。这说明更新账本后，成本公式可能用缓存复用换取较低负载；影子计算并不是一次真实关闭 Progress 的回放。
这个请求在独立的 KV 和 KV+Progress 诊断中，新算 token 分别为 17,728 和 49,664；但两轮请求到达偏移分别为 11.49 s 和 17.58 s，缓存状态和竞争不同，不能把实际差额全部归因于这一条影子选路。

## 与无埋点性能组的关系

无埋点性能组中，Progress 使新算 input token 从 3,614,800 增加至 4,009,920（+10.93%），总吞吐变化 -6.67%；带埋点诊断中，新算 token 变化 -1.59%，总吞吐变化 +3.54%。
两个对照方向相反，埋点、闭环到达、缓存竞争和随机性均可能改变轨迹；不能把某一次的升降当作稳定收益或稳定劣化。
